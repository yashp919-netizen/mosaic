# Mosaic v2 Roadmap — Deferred Items

This document records everything that was intentionally deferred from v1, with the rationale for each deferral. See ADR-0003 for the scoping decision that produced this list.

---

## Deferred Agents

### Alchemist (transformation code generator)
**What:** Given a confirmed source-to-target mapping, generate Python/SQL transformation code that handles the specific conversion (e.g. DD/MM/YY → ISO 8601, ounces → grams, category code → canonical path).

**Why deferred:** Requires a self-testing loop (generate code → run on sample → verify output schema) that adds significant complexity. v1 ships `transformations_applied: []` as an honest placeholder in every `LineageRecord`.

**In the code:** `src/mosaic/agents/scribe.py` — `transformations_applied=[]` with an explicit comment.

**v2 plan:** Implement `src/mosaic/agents/alchemist.py`. Insert an `alchemist_node` between `finalize_node` and `scribe_node` in the LangGraph graph.

---

### Sentinel (output validator)
**What:** Adversarial agent that checks the harmonized master for constraint violations, referential integrity, and schema conformance before go-live sign-off.

**Why deferred:** Validation rules are domain-specific and require sample real-world schema definitions we don't have in v1.

**v2 plan:** Implement `src/mosaic/agents/sentinel.py`. Insert after `scribe_node`. Output: a `ValidationReport` Pydantic model with pass/fail per constraint.

---

## Deferred Infrastructure

### Gemini / Vertex AI LLM client
**What:** `src/mosaic/llm/gemini.py` and `_get_gemini_client()` in `factory.py` are scaffolded but `get_llm("gemini")` raises `NotImplementedError`.

**Why deferred:** Requires Google Cloud Application Default Credentials setup. Deferred to the comparative benchmark (Day 9).

**In the code:** `src/mosaic/llm/factory.py:_get_gemini_client` — `raise NotImplementedError`.

**v2 plan:** Use `google-cloud-aiplatform` SDK with `instructor` patching. Wire ADC authentication with a clear failure message.

---

### FastAPI REST layer
**What:** `src/mosaic/api/main.py` is an empty stub. v1 has no HTTP API; all interaction is via CLI or Streamlit.

**Why deferred:** CLI and Streamlit cover the demo use case. A REST API adds surface area without benefiting the benchmark.

**v2 plan:** Expose `POST /run` (trigger pipeline), `GET /status/{run_id}` (poll), `GET /results/{run_id}` (fetch proposals + lineage). Async via FastAPI + LangGraph persistence.

---

## Deferred Features

### Cross-market entity resolution (golden record)
**What:** Detecting that `UK-12345`, `IN-AB9901`, and `BR-X7723` are the same product concept, and producing a single golden master record with the best value per field across markets.

**Why deferred:** Requires fuzzy matching + embedding-based deduplication at scale. v1 maps each market independently.

**v2 plan:** Add a `resolve_node` after all three markets are harmonized. Use FAISS to find near-duplicate embeddings across markets; present clusters to a human reviewer.

---

### Allergen detection from free-text ingredients
**What:** Parsing unstructured ingredient lists (e.g. "contains milk, wheat flour, soya lecithin") into standardized allergen codes aligned with EU CLP Regulation and Indian FSSAI.

**Why deferred:** Requires a domain-specific NER model or a fine-tuned classifier. Out of scope for a mapping-focused v1.

**v2 plan:** Integrate a food-NER model (e.g. spaCy with a custom pipeline) or a prompt-based extraction step in Scout's characterization pass.

---

### Compliance hooks (EU CLP / Indian FSSAI)
**What:** Regulation-specific validation rules that check whether allergen declarations, category codes, and labeling fields meet local legal requirements.

**Why deferred:** Requires up-to-date regulatory reference data and legal review. Purely informational in v1.

**v2 plan:** Implement as pluggable `ComplianceChecker` classes called by Sentinel.

---

### Vertex AI deployment path
**What:** An ADR and implementation guide for running the full Mosaic pipeline on Google Cloud (Cloud Run + Vertex AI Pipelines + BigQuery lineage store).

**Why deferred:** The public announcement context (Unilever × Google Cloud) makes this a natural v2 deliverable. v1 ships as a local-first demo with a HuggingFace Spaces option.

**v2 plan:** ADR-0004 (Vertex AI deployment). Dockerfile variant using Vertex AI as the LLM backend. BigQuery table for lineage records instead of JSONL files.

---

## Known Calibration Note

The confidence calibration (ECE) was measured on synthetic data generated by the same distribution the system was trained on (via heuristics tuned to that schema). Calibration on real-world CPG product masters will differ. A re-calibration pass against real data is a v2 priority.
